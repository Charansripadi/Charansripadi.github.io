Fine-tuning · Calibration · MLOps

TinyJudge: a fine-tuned, calibrated judge for AI agent behaviour

LLM judges are slow and costly for simple yes/no checks and give no calibrated confidence, a gap raised in AWS Strands Agents #4585. TinyJudge fine-tunes ModernBERT-base (150M parameters) to check policy compliance, tool choice and whether replies are faithful to tool results, then escalates only the uncertain cases to an LLM.

88.0% vs 81.2%accuracy vs a 27B LLM judge, 208 real agent conversations
ECE 0.20 to 0.10calibration error halved; faithfulness accuracy rose from 74% to 84%
89.9% · 35%cascade accuracy, with only 35% of cases sent to the LLM
  • Versioned dataset (SHA-256 manifest) from rule-labelled agent trajectories and LLM-written replies.
  • MLflow tracking, Colab GPU training, Hugging Face Hub as a tagged model registry.
  • FastAPI service with Prometheus metrics and drift signals; Docker image built, smoke-tested and benchmarked by GitHub Actions behind an accuracy quality gate before publishing.

Multi-agent · Google ADK · Evaluation

SkillMiner: turning agent traces into validated skills

Agents re-derive the same procedures in every conversation and skip steps along the way. SkillMiner, built on Google ADK, finds the workflows an agent keeps repeating and writes them as Agent Skills (SKILL.md) that ADK loads natively. It is a working answer to Google ADK #5398.

ARI 0.93 vs 0.48LLM intent mining vs a TF-IDF clustering baseline
75% to 100%procedure compliance with mined skills (pilot A/B, 8 pairs)
1 to 0policy violations; the refund skill learned the rule from traces
  • ADK trace-recorder plugin, LLM customer simulator with personas and hidden ground truth.
  • Privacy Guard that redacts personal data using values seen in tool calls; paired A/B Validator (exact McNemar); Drift Watcher that retires skills when tools change.
  • Fixed a bug where retrying a rate-limited agent turn ran refund and email tools twice. Retries now happen per model call.
